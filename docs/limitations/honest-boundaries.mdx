# 诚实边界

## 不识别人

协议里没有「人类分数」。验证通过只说明**这份答案与这道挑战匹配**，不说明提交者是谁、是不是真人、过去做过什么。任何把结果当身份结论使用的做法，都超出了它的能力范围。

## 成本可以被支付

计算成本对访客是几十毫秒，对攻击者是叠加的 CPU 账单。拥有大量算力或由真人操作的一方仍然可以逐次通过。合理的搭配是：

- 账号与邮箱维度的频率限制
- 全局发信 / 注册额度
- 关键操作的二次确认

## 一次性是进程级的

兑换占位记录不跨实例共享；兑换令牌在有效期内可重复使用于**同一用途**。这两点都不是缺陷，而是「不引入共享存储」这一选择的直接结果。详见[多实例部署](../advanced/multi-instance.mdx)。

## 浏览器能力是前提

没有 Worker / WASM 的环境无法求解，会明确报错。这不是「降级放行」的设计 —— 静默放行会让验证形同虚设。

## 不解决的业务问题

| 问题 | 归属 |
| --- | --- |
| 弱密码、撞库 | 认证策略 |
| 垃圾内容 | 审核与权限 |
| 额度滥用 | 业务限流 |
| 账号盗用 | 会话与二次验证 |

:::info

NSCHA 是这些策略前面的一道门槛，不是它们的替代品。

:::
