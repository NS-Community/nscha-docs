# 为什么是计算成本

批量滥用有一个共同点：**同一个人要发出成千上万次请求**。只要每一次请求都必须附带一份无法预先批发、也无法复用的计算结果，规模化就不再是免费的。

## 成本曲线

一次普通提交的代价，和一次批量提交的代价，来自同一条曲线：

| 行为 | 单次 | 一万次 |
| --- | --- | --- |
| 无成本校验 | ~0 ms | ~0 ms |
| NSCHA（默认难度） | ~20 ms | ~200 s 的 CPU 时间 |

对访客来说 20 毫秒接近于无感；对脚本来说，这个数字乘以请求数就变成实打实的电费和时间。难度以「哈希前导零的个数」计量，**提高一档，期望尝试次数就近乎翻倍**。

## 为什么不用其他信号

| 信号 | 为什么放弃 |
| --- | --- |
| Cookie / 本地存储 | 形成跨访问标识，与「零持久标识」冲突 |
| 鼠标轨迹、点击节奏 | 属于行为采集，且对辅助技术不友好 |
| IP 与设备指纹 | 会连坐同一 NAT 后的正常用户，也无法自证清白 |
| 图像谜题 | 打断操作，对视障与低带宽访客不友好 |

计算成本是少数**不需要了解访客**就能成立的信号：题目是公开的，答案是算出来的，服务端只需要验证答案。

:::caution

**别把难度当成绝对防御** — 计算成本抬高的是攻击的边际成本，不是一道不可逾越的墙。它应当与频率限制、账号策略配合使用。

:::
