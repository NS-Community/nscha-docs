# NSCHA 是什么

NSCHA 是 **Non-Surveillance CAPTCHA for Human Authentication** 的缩写。它是一套部署在自有服务上的验证协议，用来回答一个很窄的问题：**这次提交是否付出过约定的计算成本？**

它刻意不回答「屏幕前是不是真人」这个更宽的问题。识别人需要观察人 —— 采集行为、留存标识、跨站比对 —— 而这些恰恰是我们不想做的事。

## 一句话描述

> 服务端签发一道可自行验算的计算题，浏览器算完再提交；服务端只认答案，不认访客。

## 组成

| 部分 | 位置 | 职责 |
| --- | --- | --- |
| 挑战签发 | 服务端 | 生成带签名的参数，不落库 |
| 求解器 | 浏览器 | 在 Worker 中完成哈希搜索 |
| 兑换接口 | 服务端 | 验签、验算、签发短时效令牌 |
| 校验接口 | 服务端 | 在处理数据之前校验令牌用途与时效 |
| 验证组件 | 页面 | 串起上述流程，把令牌交给表单 |

五块都在同一份可独立部署的仓库（`nscha-widget`）里：一个无状态函数提供三个接口，一个单文件脚本提供验证组件。没有外部 SDK，也没有需要注册的开发者账号。

## 名字里的三个承诺

- **Non-Surveillance**：不采集行为，不写持久标识，不向第三方发起请求。
- **CAPTCHA**：仍然是一道区分「一次人工提交」与「批量自动提交」的题，只是题目换成了计算量。
- **Human Authentication**：验证的对象是**提交动作**，不是人的身份。我们不做账号画像，也不给访客打分。

:::info

本站的接口路径、字段名与代码都对应独立可部署的 `nscha-widget` 服务，可直接复制使用。gamesense 论坛是它的第一个使用方，接口挂在 `/api/auth/captcha/` 前缀下，协议相同。

:::
