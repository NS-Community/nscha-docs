# 它不做什么

把做不到的事写清楚，和把做到的事写清楚一样重要。下面这些**不是** NSCHA 的目标。

## 不判断「你是不是人」

由真人逐个操作的打码农场依然可以完成验证，只是每一次都要付同样的计算成本。协议里没有「人类分数」，也没有任何基于身份的结论。

## 不做跨站去重

我们不写 Cookie，不读本地存储，不建立设备标识。同一个访客在两台设备上的两次验证，在服务端看来就是两次互不相干的计算。

## 不替代业务风控

NSCHA 只回答「这份答案是否与这道挑战匹配」。以下都需要业务侧自己处理：

- 密码强度、撞库检测与登录失败次数
- 注册频率、邮箱冷却与全局发信配额
- 内容审核、权限与封禁

## 不承诺绝对不可重放

兑换记录保存在**进程内**，多实例之间并不共享；兑换令牌在其有效期内也不做全局一次性消费。真正的保证来自短时效、用途绑定与签名，而不是实例间的共享内存。详见[诚实边界](../limitations/honest-boundaries.mdx)。

## 不适配无浏览器能力的环境

求解在 Web Worker 与 WebAssembly 中进行。缺少这些能力的客户端会收到明确的错误提示，而不是被静默放行。纯命令行客户端若需要接入，应走单独的服务端授权通道。

:::tip

如果你需要的是「识别真人」「跨站追踪」或「风险评分」，那属于另一类产品，NSCHA 明确不做。

:::
