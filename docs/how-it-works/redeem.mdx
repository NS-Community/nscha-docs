# 兑换令牌

浏览器把解交回 `POST /api/auth/captcha/redeem`：

```json
{
  "token": "<挑战令牌>",
  "solutions": [{"i": 0, "n": 3812}, {"i": 1, "n": 1177}]
}
```

`solutions` 里每项给出子挑战序号与命中的计数器值。服务端据此重新计算哈希即可验算，不需要信任客户端报告的「算了多少次」。

## 服务端四步

1. **验签** — 确认挑战令牌由本服务签发、未过期、参数未被改动
2. **验算** — 按 `c / s / d` 重放每个答案，任一不匹配即拒绝
3. **占位** — 用同步的「不存在才写入」操作确认这份挑战没被兑换过
4. **签发** — 返回一枚短时效、绑定用途的兑换令牌

第 3 步必须是**同步原子**操作。若先查询再写入，两个并发兑换可能同时通过检查。

## 兑换令牌里有什么

| 内容 | 作用 |
| --- | --- |
| 专用标记 | 与普通会话凭证区分开，防止同密钥令牌被冒充 |
| 用途 `scope` | 限定这张表单 |
| 过期时间 `exp` | 限制令牌在客户端的可用窗口 |

:::caution

**一次性的是兑换，不是令牌** — 同一份挑战只能兑换一次。但兑换出来的令牌在有效期内不做全局一次性消费，校验函数只验签、验时效与用途。本站凡提到「一次性」，指的都是兑换这一步。

:::

## 失败响应

兑换失败统一返回简短错误，不细分是验签还是验算出错。客户端应清空旧令牌并重置组件后允许重试。
