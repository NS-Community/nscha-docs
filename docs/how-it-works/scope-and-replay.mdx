# 作用域与重放

作用域绑定和重放防护解决两件不同的事：**令牌用在哪**、**答案能不能再用**。

## 用途如何注入

每次挑战 / 兑换请求都带一个自定义请求头：

```text
x-captcha-scope: login
```

服务端把作用域写进兑换令牌。业务接口校验时传入自己期望的用途，两者必须一致：

```js
await fetch('https://your-nscha-host/verify', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ token: req.body.nschaToken, scope: 'login' }),
})
```

白名单只有 `login` / `register` / `reset`。新增表单要先登记，否则令牌会被拒。

## 三类重放

| 攻击 | 防护 |
| --- | --- |
| 同一份答案兑换两次 | 进程内同步占位，第二次兑换直接拒绝 |
| 用登录令牌调注册接口 | 用途不匹配 |
| 用会话令牌冒充验证令牌 | 令牌里必须有专用标记 |

## 专用标记为什么必要

验证令牌与会话令牌可能由**同一套签名机制**签发。如果校验函数只验签，攻击者拿自己的登录凭证就能通过人机验证。因此校验函数必须额外要求令牌里存在「这是验证令牌」的标记。

:::caution

**多实例的边界** — 占位记录保存在单个进程内，实例之间不共享。因此「同一份挑战只能兑换一次」是进程级保证，不是全局保证。跨实例时真正兜底的是短时效、用途绑定与签名，详见[多实例部署](../advanced/multi-instance.mdx)。

:::
